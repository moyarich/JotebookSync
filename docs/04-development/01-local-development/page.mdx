# Local development

This guide covers the normal JotebookSync development loop.

## Install dependencies

From the repository root:

```sh
npm install
npm --prefix webviews-ui install
```

## Build the extension

Build the React webviews and TypeScript extension runtime:

```sh
npm run compile
```

The VS Code extension entry point is compiled from `src/` into `out/`. The
webview UI is built separately from `webviews-ui/`.

## Watch while developing

Run both the webview and extension compilers in watch mode:

```sh
npm run watch
```

You can also watch them independently:

```sh
npm run watch:extension
npm run watch:webview
```

## Launch the Extension Development Host

Use VS Code's extension debugging configuration or run:

```sh
npm run dev:extension
```

When testing interactively, verify behavior from the same surfaces available to
users:

- Command Palette
- Explorer **JotebookSync** context menu
- notebook toolbar
- **JotebookSync: Paired Files** Explorer view
- pairing, conversion, and freshness webviews

## Webview development

Run the standalone preview shell with:

```sh
npm run dev
```

Preview pages use clean URLs:

```text
/previews
/previews/pair-setup
/previews/freshness-report
/previews/convert-file
```

You can open a specific screen directly with `npm run dev:pair-setup`,
`npm run dev:freshness`, or `npm run dev:convert`.

Preview code lives in `previews/`; production browser code stays in
`src/webview-ui/`. Both the extension runtime and production webview bundles
are generated under `out/`.

## Package a VSIX

Build and package the extension locally:

```sh
npm run package
```

To inspect the files that would be included in the package:

```sh
npm run package:ls
```

## Demo workflows

The repository includes demo tooling under `scripts/demo/` to validate and capture
the primary extension workflows:

```sh
npm run demo
npm run demo:all
npm run demo:freshness
npm run demo:round-trip
npm run demo:formats
npm run demo:gif
```

Demo recordings are written to `scripts/demo/artifacts/` and are ignored by Git.
`npm run demo:gif` converts those recordings into the committed README/Marketplace
GIFs under the repository-root `media/` directory.

Keep README screenshots and GIFs representative of the actual extension
behavior when user-facing workflows change.
